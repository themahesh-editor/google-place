ATTACHAI FULL SYSTEM — हिंदी सेटअप गाइड
========================================

इस ZIP में पूरा Python app, Supabase/PostgreSQL migrations, GitHub Actions workflows,
operational monitor.yaml, tests, README और example environment file शामिल हैं।
Quality-fix लागू है; यह केवल patch ZIP नहीं है।

पहले सुरक्षा
------------
1. अपने GitHub repository की वर्तमान copy/branch का backup लें।
2. Supabase की मौजूदा tables और data को manually delete न करें।
3. reset_state=false रखें। वास्तविक emails की सुरक्षा के लिए send_enabled=false और
   dry_run=true रखें; example config भी इन्हीं safe defaults पर है।
4. इस ZIP की migrations को production Supabase पर चलाने से पहले README में
   legacy-schema migration वाला भाग पढ़ें। Compatibility migration पुरानी पहचान वाली
   tables में data मौजूद होने पर जानबूझकर रुक सकती है; data मिटाने के बजाय पहले
   schema/data migration plan बनाएं।

स्थानीय परीक्षण
--------------
Python 3.11 के साथ project root (जहाँ requirements.txt है) में चलाएँ:

  python -m pip install -r requirements.txt
  python -m unittest discover -s tests -p 'test_*.py' -v

इस पैकेज में इन unit tests को चलाने पर 62 tests पास हुए। ये SQLite और fake providers
का उपयोग करते हैं; इससे live Google Places, NVIDIA, Supabase, SMTP या IMAP की
उपलब्धता प्रमाणित नहीं होती।

GitHub पर लगाना
---------------
1. ZIP extract करें।
2. Project के files अपने repository की working branch में copy/replace करें; ZIP को
   repository में एक अकेली file की तरह upload न करें।
3. git diff देखें और फिर tests चलाएँ। केवल review के बाद commit/push करें।
4. GitHub Secrets/Variables को मौजूदा repository में सुरक्षित रखें; उन्हें source में
   न लिखें। .env.example सिर्फ नाम और placeholders दिखाता है।
5. पहले छोटा manual dry run करें: target_new_initials=2, reset_state=false,
   send_enabled=false, dry_run=true.
6. Log में DISCOVERY_PROGRESS, CANDIDATE_EVALUATION, RESEARCH_FAILED,
   PERSONALIZATION_FAILED और FINAL_SUMMARY देखें। फिर ही वास्तविक भेजने के बारे में
   निर्णय लें।

Quality fixes
-------------
- Non-HTTP/HTTPS, malformed तथा telephone-जैसे website URLs सुरक्षित रूप से reject होते हैं;
  खराब href पूरे crawl को crash नहीं कराता।
- एक dict वाला JSON array unambiguous होने पर object operations के लिए unwrap होता है।
- स्पष्ट social/profile/directory website domains को crawl/LLM research से पहले filter किया जाता है।
- पुरानी crawler port-parse error से रुके retryable candidates को startup पर narrow rule से
  फिर प्रयास के लिए schedule किया जाता है; बाकी retry timers/status नहीं बदले जाते।
- Google Places request budget 60 से 120 किया गया है। इससे usage/billing बढ़ सकती है; Google
  account की quota और billing limits जाँचें।
- Resume, idempotency और follow-up sequence के लिए existing tests मौजूद हैं।

महत्वपूर्ण सीमा
---------------
100 का लक्ष्य 100 सफल INITIAL SMTP sends है, न कि केवल 100 खोजे गए leads। पर्याप्त valid
businesses/emails न मिलने, API quota/provider failure या runtime limit पर लक्ष्य अधूरा रह
सकता है। ऐसी स्थिति में log में कारण देखें और durable DB state के साथ अगली run में resume करें।
कोई भी search system वैध candidates की उपलब्धता की गारंटी नहीं दे सकता।
